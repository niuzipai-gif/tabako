# 一カートン、AI 进度与独立排行设计说明

## 目标

移动端优先解决三个判断任务：

1. 用户能明确区分“单包”和“一カートン（通常 10 包）”，并知道图片是否已经核对。
2. 用户点击 AI 后立刻看到真实执行阶段；在线代理不可用时，必须明确结束在“未上传 / 未执行在线识别”，不能像卡死。
3. 排行从首页横向预览升级为独立的纵向信息流，分别查看日本人与中国游客的编辑指数。

## 媒体可信度

- 不用生成图或相似图冒充真实烟盒、整条外箱。
- 每个条目都提供精确的“一カートン”检索词、Google 图片入口和来源状态。
- 已核对的真实整条图可直接展示；未核对的条目显示明确的待核对状态，不展示错误图片。
- 已知重复图片必须进入审计清单：真实同款、包装形态不同、或图片尚未核对，三种情况分别说明。
- “セブンスター”与“セブンスター ボックス”保留为两个真实 SKU，分别标注软包与硬盒，不能因为正面设计相近而误合并。

## AI 状态机

- 偏好匹配：理解输入 → 本地目录匹配 →（可选）安全代理 → MiniMax 增强 → 完成。
- 拍照识别：检查图片 → 检查安全代理 → 上传 → MiniMax 识别 → 本地目录映射 → 完成。
- 进度只能随真实程序节点前进，不使用伪造计时器。
- 所有结束状态必须为完成、受阻或失败之一，并给出下一步。

## 排行页面

- 新增 `ranking.html`，维持原 GitHub Pages 路径与现有视觉系统。
- 顶部提供日本 / 中国游客切换，下面为从上到下的信息流。
- 每一项展示名次、真实包装图、分数、受欢迎原因、价格和渠道状态。
- 点击条目返回首页并直接打开对应商品详情。

## 验收

- 自动测试覆盖媒体元数据、重复图审计、AI 进度壳、排行独立页面。
- 在 390×844 与桌面视口分别核对首页、商品详情、AI 和排行页。
- 视觉 QA 结论写入 `design-qa.md`。
